## Key Points

- The author built a Zstandard decompressor in Lean to explore dependent types and LLM-powered proof automation
- Dependent types (like those in Coq, Rocq, and Lean) allow encoding and enforcing subtle invariants in type systems that would normally be comments in traditional languages
- Traditional proof effort has been a major barrier - the seL4 project found 10x more time spent proving than implementing, with 20x more proof code than C code
- LLMs combined with proof irrelevance now offer capable proof automation, potentially making dependent-type systems dramatically more practical
- Zstandard is winning as gzip's replacement, offering better entropy coding and impressive decompression speeds
- Zstandard uses both Huffman trees and a higher-compression entropy encoder called FSE (Finite State Entropy) which uses state machines for fractional-bit encoding
- Lean is a strict, purely functional language with advantages over Haskell including no laziness surprises, nice imperative-style sugar with monadic do notation, and in-place mutation optimizations
- The author proved universal properties of the FSE table construction algorithm in Lean with LLM assistance in about 20 minutes
- The combination of dependent types and LLM proof automation could represent a new type of practical programming language for software engineering
- The article also explores verified assembly using AWS's LNSym simulator for AArch64 and attempts to prove equivalence between optimized assembly and Lean code
