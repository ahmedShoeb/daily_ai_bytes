## Key Points

- The article discusses how to properly measure Python's free-threaded mode, showing there are actually three configurations to compare, not just two.
- In Python 3.14, the free-threaded mode is now officially supported with a 5-10% performance overhead, down from substantial single-threaded performance hits in earlier versions.
- The three configurations are: default Python 3.14 (GIL-enabled), Python 3.14t with GIL enabled (-X gil=1), and Python 3.14t with GIL disabled (-X gil=0).
- The article provides a benchmark harness that properly checks which configuration is actually running, crucially importing dependencies before testing since some packages can re-enable the GIL.
- Test results show that with GIL disabled, performance scales nearly perfectly on 8 threads, while both GIL-enabled configurations show no scaling improvement.
- The article warns that Python's built-in container internal locks are not guaranteed for thread safety and recommends using explicit synchronization primitives.
- Key advice: measure the parallel win (ft-gil vs ft-nogil) rather than the overhead tax, as the parallel benefit is obvious while overhead is small and confounded by toolchain differences.
- The experiment demonstrates 4.9x-5.2x speedup on 8 threads when properly measuring free-threaded Python with GIL disabled.
