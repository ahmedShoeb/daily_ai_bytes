## Key Points

- Prompt caching is crucial for coding agents using LLMs because most of the prompt input repeats across requests, and recomputing entire prompts for every turn is slow and expensive
- The KV cache stores computed attention state from tokens, allowing models to reuse previous computations for matching prefixes in subsequent requests
- There are two main approaches to storing caches: session affinity (keeping cache on same GPU) and distributed caching (making cache available across workers)
- Tool definitions and dynamic prompts can invalidate caches, as changes to tool loadouts or system prompts move the mismatch point early in the prompt
- Additive tool loading is now supported by some models, allowing tools to be added later in conversation without breaking existing cache
- Cache time-to-live (TTL) affects cost - Anthropic has a default 5-minute cache that can expire during breaks, leading to expensive full recomputations
- Cache misses can be surprisingly expensive - processing 100,000 token history again can cost more than generating new responses
- Pi (the coding agent) shows cache statistics including hit rates, re-billed costs, and provides warnings for significant cache misses
- Pi doesn't aggressively prune conversations because deleting content from the middle changes the prefix and forces recomputation of everything after it
- Common reasons for poor cache performance include idling beyond TTL, model/provider switches, branch navigation, tool changes, and dynamic prompts
