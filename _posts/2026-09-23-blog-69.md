## Key Points

- Using simple 'string contains' checks for AI coding agent evals can provide false assurance about what's actually been proven
- These deterministic graders only prove that a specific string appears in the output, not that the intended functionality exists
- For example, checking for 'Azure' in generated code only proves the word appears - it could be in comments, dead code, or unused dependencies
- The author suggests completing two sentences for any eval: 'If this grader passes, I now know that ___' and 'If this grader fails, I now know that ___'
- LLM judges can handle semantic questions better than deterministic graders, but still can't replace actual compilation and execution
- The article recommends treating agentic evals like integration tests with separate gates for building, testing, running, and deploying
- Deterministic tools should be used when they can directly answer questions (like compilers verifying compilation)
- The key insight: evals become trustworthy only when their evidence supports the claims you make from them, not just because they run frequently
