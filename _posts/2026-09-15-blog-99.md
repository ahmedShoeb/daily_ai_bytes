## Key Points

- Candace Wilson and her design team aimed to create AI-assisted prototypes with reusable code to preserve design details during handoff
- They discovered that prototypes that looked 'almost finished' often contained thousands of lines of unclear code, poor component boundaries, and mismatched implementations
- AI-generated code created an 'architectural handoff gap' where developers had to interpret, refactor, or rebuild the work before it fit production environments
- The problem was that design moved faster but simply pushed the effort downstream to development teams
- Wilson distinguishes between disposable prototypes (which can have looser code) and prototypes meant for team handoff
- She introduces the principle: 'Prototype code does not need to be production-ready, but it should be production-useful'
- Production-useful means code should be structured enough that development can extract from it without untangling everything
- Component boundaries should be clear, reusable pieces actually reusable, and responsive behavior should match design intent
- The prototype doesn't need to mirror the production codebase exactly, but should be close enough to preserve speed gains from building in code
