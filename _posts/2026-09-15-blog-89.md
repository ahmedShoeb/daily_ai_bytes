## Key Points

- The author traced a slow test suite issue through multiple layers: Vitest (test runner) → Node.js → V8 JavaScript engine
- The problem involved a combination of Vitest's mock cleanup inefficiency (already being fixed) and a V8 cache collision issue exposed by a Node.js upgrade
- By creating a minimal reproduction case, the author identified a specific V8 cache optimization problem where different object types competed for the same cache entry
- The author submitted a patch to V8 that improved the cache hash selection, resulting in an 8x speedup for the affected operation
- The fix was reviewed and merged by V8 maintainers within about 2.5 days, demonstrating efficient open-source collaboration
- Multiple fixes were implemented across three layers: Vitest reduced unnecessary work, Node.js added a temporary mitigation, and V8 fixed the underlying engine issue
- This experience highlighted the 'coordination tax' - the extra effort needed when changes must pass through separate projects with different release schedules
- The author argues that companies practicing InnerSource should reduce unnecessary separation between teams when they own both sides of interdependent code
- Companies have an advantage over open-source projects: they can change shared code and its consumers together without treating internal teams as separate suppliers
