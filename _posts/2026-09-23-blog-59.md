## Key Points

- AX is a high-throughput declarative orchestrator designed to run billions of autonomous agent workloads in a cluster
- It provides Kubernetes-like functionality but specifically built for agent workloads that are neither stateless microservices nor batch jobs
- The system uses four core primitives: Task (for isolated sandbox execution), Workspace (for pre-wired environments), Gateway (for network traffic control), and Model (for LLM configuration)
- AX can pause idle agents with `ax suspend` and resume them exactly where they left off with `ax resume`
- The system includes debugging capabilities allowing developers to SSH into running agent sandboxes to monitor activity
- Configuration is done through YAML manifests similar to Kubernetes resources with `ax.io/v1alpha1` API version
- Deployment requires a Kubernetes cluster, container registry, and Agent Substrate Control API connectivity
- The command-line interface is deliberately designed to be kubectl-shaped with commands like `apply`, `get`, `describe`, `watch`, and `delete`
- AX follows the active Kubernetes context and can automatically tunnel to different clusters' control planes
- Google warns that the project is still in active development with major breaking changes expected before stable release
