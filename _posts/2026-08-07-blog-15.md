## Key Points

- A 16-character prompt generated a 42,980-byte request, with only 25 tokens (0.3%) coming from the user prompt and the rest from Codex's internal structures.
- Codex's requests include instructions, tool definitions, permissions, skill metadata, environment context, and request framing, with three main components accounting for 7,696 of 9,435 tokens.
- Project instructions from AGENTS.md files are transmitted fully, with larger instruction files significantly increasing request size (1,000 markers added +11,030 tokens).
- Repository skills only initially contribute name/description/path metadata - their full bodies appear only after being read.
- MCP tool descriptions are deferred until discovery, with tool descriptions appearing only after the exec interface triggers their inclusion.
- File contents, terminal output, and images don't appear in requests until explicitly read or generated, but once included, they persist in subsequent requests.
- Large files and command outputs get truncated to head-and-tail samples before transmission to manage request size.
- Images are transmitted as base64-encoded data URLs, with Codex resizing and re-encoding larger images before transmission.
- Codex implements history compaction by sending accumulated history to another model request for summarization, then replacing raw history with the summary.
- The experiment revealed what information crosses the "machine boundary": some data is always present (instructions, tools), while other data appears only after specific actions (file reads, commands).
