## Key Points

- WorkOS has introduced a Management MCP (Model Context Protocol) server that exposes the full management surface of WorkOS accounts as tools that AI agents can use
- The server allows AI agents to perform configuration tasks that previously required human interaction with the dashboard, including managing organizations, SSO connections, Directory Sync, AuthKit users, and more
- The MCP server uses OAuth authentication and inherits the exact same roles and permissions as the user's dashboard login - no separate permission model is required
- The server includes built-in safety measures: excludes credential-minting operations, user impersonation, and billing flows; strips secret fields from responses; and requires two-call confirmation for irreversible deletes
- Agents interact with the server through four main tools: whoami, list_operations, query, and mutate - avoiding context window overload from hundreds of individual endpoints
- Team admins can control MCP access through three settings: enable/disable overall access, restrict to sandbox environments only, and restrict to read-only operations
- Setup is simple with a single command that initiates an OAuth flow, working with Claude Code, Cursor, Codex, ChatGPT, and other agents that support remote MCP servers
- The MCP server is designed to work remotely from any device without a local development environment, complementing the existing WorkOS CLI which requires a terminal setup
- Practical use cases include debugging sign-in problems, onboarding new customers, auditing configurations, managing users, and streaming audit logs to monitoring tools
