## Key Points

- Cursor is launching 'Projects', a feature that enables developers to handle larger bodies of work like features, migrations, or full applications
- Projects maintain context over months of work, delegate tasks to thousands of subagents, and perform recurring work without prompting
- The system operates with a coordinator agent that directs subagents rather than executing code itself, making it always responsive
- Three core capabilities enable Projects: cloud computing by default with local testing when needed, shared context that grows over time, and subscriptions that trigger action on signals like Slack messages or PR merges
- Cursor's internal testing shows substantial productivity gains: new users merge 30% more PRs, while users primarily using Projects merge six times as many
- The company identifies three primary use patterns: feature work, migrations (especially across hundreds of PRs), and 'gardening' for ongoing maintenance tasks
- Projects have already been used internally for months at Cursor for tasks like migrations, design system consistency, and building the Projects feature itself
- One example shows a design-system Project that can handle 20 to 100 PRs daily by extracting components and adding lint rules automatically
- Projects are now available in beta and rolling out to all users, with the recommendation to use them for work that extends beyond a single chat session
