## Key Points

- The article introduces LLMTraceFX, a tool that validates KV (key-value) cache claims in LLM inference systems
- It demonstrates how cache hits can be faked or misreported - engines can claim cache hits while still processing tokens
- The auditor uses five independent checks: token oracle, observed prompt work, output-token identity, evaluator correctness, and checksum-bound evidence bundle
- Equal token count doesn't guarantee equal token identity - requests can have same length but different token IDs, leading to cache misses
- The system distinguishes between different types of misses: cold misses (no candidate), namespace isolation (different namespace), and eviction (previously resident candidate removed)
- A cache event only becomes evidence when multiple independent verifications align: expected prefix, engine attestation, skipped work, identical output, and evaluator passing
- The tool was demonstrated with 10 test cases covering various scenarios like exact duplicates, interior mutations, boundary mutations, and namespace isolation
- The article emphasizes that simply reporting a cache hit doesn't prove work was skipped - the auditor provides verifiable proof
- Important limitations: The demo doesn't prove production cache correctness, GPU performance, latency reduction, or runtime-memory savings - it focuses on verifying cache claims at token level
