## Key Points

- Kiro originally had three separate agent architectures (IDE, CLI, web) each with different implementations, session formats, and tool sets
- The team consolidated these into a single unified agent harness to enable seamless session movement across different surfaces (laptop, cloud, mobile)
- The harness was built as a standalone server process using Agent Client Protocol (ACP) for communication between clients and the agent
- This architecture allows features to be built once and deployed across all clients (IDE, CLI, web, iOS) with zero client-side changes in many cases
- Kiro added Kiro-ACP extensions on top of ACP to support features like live steering, spec-driven development, and rich permission systems
- The new harness introduces a capability-based permission model using Cedar policy language, grouping tools by functionality (fs_read, fs_write, shell, etc.)
- Features like spec-driven development, custom agents, and hooks now work consistently across all clients with the same configuration formats
- The unified architecture has already enabled features like global hooks and policy presets that work across all clients with just harness updates
- The architecture makes future capabilities like session packaging and cross-environment session movement easier to implement
- All four Kiro clients (IDE 1.0, CLI v3, web preview, iOS preview) now run the unified harness
